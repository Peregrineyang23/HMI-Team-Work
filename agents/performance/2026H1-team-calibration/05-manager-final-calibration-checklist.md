# Manager Final Calibration Checklist

- release_level: PRIVATE

Use this checklist before finalizing each 2026H1 score.

## 1. Identity And Scope

- [ ] Member is active in current roster.
- [ ] Member is included in the manager-approved active calibration cohort.
- [ ] Evaluation period is 2026-01-01 to 2026-06-30.
- [ ] 2026-07 data is used only as background unless explicitly approved.
- [ ] Current file size/page/node count is not backdated without an H1 snapshot or timestamped version.

## 2. Evidence Coverage

- [ ] Evidence index exists.
- [ ] At least 3 evidence categories are attempted.
- [ ] High-score claims have S/A evidence.
- [ ] Evidence grade is capped by the weakest inaccessible or self-reported link.
- [ ] Customer/manager recognition has accessible raw content or is capped at A / medium-high.
- [ ] Local file evidence has timestamps and desensitized paths.
- [ ] Figma evidence has file role, versions, pages/sections/artboards when available.
- [ ] Feishu messages are not used as quality proof unless content is sampled.
- [ ] Jira/Git/task evidence is used where relevant.

## 3. Score Sanity

- [ ] File count is not treated as direct performance.
- [ ] Message count is not treated as direct communication quality.
- [ ] Meeting count is not treated as direct contribution.
- [ ] AI tool claims have usage or efficiency evidence.
- [ ] Quality score above 18/20 has review/adoption/feedback proof.
- [ ] Risk closure score above 5/6 has issue closure proof.
- [ ] Full marks have a reason why B+ is insufficient.
- [ ] Coordination/leadership scores use decisions and closure outcomes, not activity counts.
- [ ] Platform/method scores distinguish creation from verified reuse or adoption.

## 4. Bonus And Deduction

- [ ] Bonus is not duplicated from normal job responsibility.
- [ ] Bonus has evidence of extra impact.
- [ ] Bonus is entered under the correct category.
- [ ] Platform/method bonus has reuse, adoption, governance, or measurable project-use proof.
- [ ] Deduction has explicit negative evidence.
- [ ] No deduction is applied from rumor or missing data alone.

## 5. Cross-Team Fairness

- [ ] Same evidence type has similar scoring effect across members.
- [ ] Missing local data does not unfairly suppress strong cloud/task evidence.
- [ ] Rich local data does not unfairly inflate weak impact.
- [ ] Owner/leader responsibility is recognized separately from raw output volume.
- [ ] Super-collaboration support roles are not compared directly with domain owner roles without role adjustment.
- [ ] Role calibration changes acceptable evidence, not the five primary weights.

## 6. Final Output

Each final score must include:

- [ ] Final score.
- [ ] Final band.
- [ ] Score range before manager calibration.
- [ ] Top 3 evidence-backed contributions.
- [ ] Key risk or uncertainty.
- [ ] Next-cycle improvement suggestion.
- [ ] Item scores, bonus, deduction, final total, and band reconcile mechanically.
